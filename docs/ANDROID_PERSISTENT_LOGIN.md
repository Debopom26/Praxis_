# Android fixed-address and remembered sign-in release

Install the latest Praxis-Caller-VoIP.apk over the existing app; do not uninstall it. Version 0.2.0 (versionCode 2) uses the same signing certificate as the prior GitHub demo APK, preserving app data and Android Keystore keys.

The app automatically uses https://praxisdashboard.debopomrc2602.workers.dev/. Server-address entry is removed. Saved native connections migrate to this origin. A still-valid old access token can automatically obtain a remembered-login grant; if an old version's token already expired before this update, sign in once because that version stored no renewal credential. Subsequent server outages and app/phone restarts preserve the remembered login. No password is stored. Clearing app data, uninstalling, account disablement, password changes or revoked membership can require sign-in again.

A random device refresh credential is encrypted with Android Keystore AES-GCM. PostgreSQL stores only its SHA-256 digest, tenant/user association, password-hash fingerprint and creation time. Normal short-lived JWT expiry remains unchanged. Refresh revalidates current account activation, password version and tenant membership/role. Deliberate logout removes local secrets immediately and revokes this device's grant when the server is reachable; another device's grant remains independent. Offline logout cannot contact the server to revoke remotely, but its local credential is erased and cannot be used to reconnect from that installation. Grants remain valid until revocation/account changes; no unexpiring access JWT or saved-password workaround was added.

During server/tunnel outages the app shows: **Server is offline — Praxis_ unavailable**. Reconnect retries automatically; no login dialog appears solely because a remembered account's access token expired offline. Authenticated calls still require an online local server and active tunnel. No physical call test is claimed by JVM/server verification.

Backend migration 0004 is deployed on real PostgreSQL. Owner executes DDL; runtime receives DML only and cannot create schema objects. Existing models, analysis contracts, scores, thresholds, Android capture and audio forwarding are unchanged. The existing native login API remains compatible; remember=true opts into a grant. Additive endpoints: /api/v1/auth/remember, /refresh and /logout. The gateway can wake the existing server for refresh/remember without forwarding credential bodies before readiness.
